# 割り込み可能なピッチキャッシュ補正

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

`TryStepPitchCache`は527c..5367を1命令境界ずつC++実行する。
キャッシュヒット判定、参照音程からの補正レート計算、補正値の除算・符号処理、
キャッシュ更新、C8B0との加算と上下限処理、voice+72への保存を扱う。
既存マスク区間の一括変換・キャッシュ合成を維持し、残る単命令経路に接続する。
debtを追加せず、割り込み・周辺装置更新を元の12cycle境界で維持。
RT確保・ロック・UI呼出しなし。

Release oracle `native-tva`で8,228ケースの各命令後のPC/SR/レジスタ/SRAMが一致。
全256source、キャッシュhit/miss、音程区切り、加算飽和・ゼロ制限を含む。
共通ガードと参照元範囲の拒否時に状態不変。
379,676ステレオフレームがビット一致。非マスクキャッシュだけの到達回数は未計数。
除数ゼロは状態を変更せずH8へ戻すが、この例外経路の専用テストは未追加。
Mac Release Shared Code（署名なし）のビルド成功。

ホスト内負荷、Windows/Linux、全音色は未検証。今回の改善率は未測定。
これでピッチ関連の単命令経路を追加したが、すべての実演奏でH8 fallbackが
消えたという監査はまだ行っていない。他EG、MIDI/GS、ボイス管理、起動等も
H8が残っており、完全置換の完了ではない。
