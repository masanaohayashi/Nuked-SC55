# 音量LFO合成の直接入口

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

`TryModulateLevel`で312b..3187の直接呼び出しをC++化する。
従来は309bの合成処理内でのみ使っていた`ModulateV121`を再利用し、
直接入口でも最終SR、R2/R3/R4/R6、命令数を保持する。
深さの符号合成、0x7f00制限、積の倍化、切り上げ、負側のゼロ飽和を扱う。
正側はフィルターLFOと異なり32767へ飽和させない。

v1.21、CP=0、mask7、traceなしを要求する。レジスタ演算のみ。
元ヘルパーの命令数からRTSを除き、3187のRTS手前までのdebtを設定。
確保・ロック・I/O・UI呼び出しは追加しない。

## 検証

- 7,679ケースでH8とPC/SR/レジスタ/SRAM/命令数が一致。
- Release oracleで379,676ステレオフレームがビット一致。
- Mac Release Shared Codeを署名なしでビルド成功。
- 今回の再生条件で全体fallbackは3,575,391のまま変化なし。
  この追加による負荷改善を確認したとはしない。

## 非マスク経路

`TryStepLevelModulation`で312b..3187の43命令（RTSを含む）を単命令C++化。
v1.21・CP=0・traceなしを要求し、割り込みマスクには依存しない。
積の下位word倍化からcarry付き上位word倍化、切り上げ、音量加減算まで
各命令の状態を公開し、debtを追加しない。RTSは既存スタック処理を使用。

- 43命令×384ケース＝16,512命令境界でH8と状態一致。
- 379,676ステレオフレームがビット一致、Mac Release Shared Codeビルド成功。
- 全体fallback: 3,575,391→3,574,541（850命令減少）。

減少は今回の限定再生での実測。CPU時間の改善率は未測定。
呼び出し前後の接続部、他の音量演算にはH8が残る。
