# ピッチEG初期化と再入場 — 2026-09-09

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

## 実装

- `TryDispatchPitchEnvelope`に4f9eからの再入場を追加。
  全12段階のテーブル分岐、前の目標値のコピー、4番目の目標/rateも扱う。
  割り込みマスク等の既存ガードを維持。単独5060も通常dispatchに接続。
- `TryInitialisePitchEnvelope`は4f51から4f5cまたは4f85までの初期設定を扱う。
  phase/cache/residual、part source、elapsedの退避と一時値1を設定する。
  BSR、RTS、elapsed復元、後段処理は元の位置に残す。
- 実再生の初期化はSR=0009、DP=0、EP=1で通ることを確認。
  マスクされたEG更新ループと異なり、初期化は割り込みを許可している。
  一括実行のガードを緩めるだけでは途中の割り込みから見える状態が変わる。
- `TryStepPitchInitialisation`はこの初期化を1命令境界ずつC++で実行する。
  opcode decodeは省くが、各命令のレジスタ/SR/SRAMをその時点で更新し、
  native_debtは増やさない。既存MCU_Stepの割り込み・タイマー更新を維持。
  EPを使う間接アクセスはないためEP=1でも可。trace時はH8へ戻す。

## 検証

- 再入場5,446ケースで全レジスタ/SR/PC/SRAM/命令数がH8と一致。
- 一括初期化5,398ケースで同じ状態・命令数を照合。
- 割り込み可能な初期化5,398ケースを各命令の直後にH8と比較。
  EP=1、SR下位全16組合せ、初期化/再入場分岐、24voiceを含む。
- ガード拒否時は状態を変更しないことを確認。
- 実再生で初期化25回。起動→24音→controller/pressure→ポルタメント→
  新規Note→Note Offの379,676ステレオフレームがビット一致。
- 再入場の一括C++経路はこの実再生では0回。到達することとガードを通ることは
  別であり、再入場を実再生で完全置換したとは扱わない。
- Mac Release Shared Code（arm64/x86_64、署名なし）ビルド成功。

```sh
cmake --build /tmp/sc55-firmware-oracle-build --target sc55-firmware-oracle -j 4
ctest --test-dir /tmp/sc55-firmware-oracle-build -R '^native-tva$' -V
```

## 残件

後続の[音程補正・段階設定の追加](NATIVE_PITCH_ADJUST_2026-09-09.md)で
一部を実装。再入場についてはガード拒否だけでなく入口の到達回数を調べ、
この演奏テストでは入口自体に到達しないことを確認した。

割り込み可能な再入場/補間/後段、初期化のサブルーチン呼出し・復元と後段分岐、
50cf..5175の補正処理はH8が残る。マスク区間の一括置換手法をそのまま
非マスク区間へ広げない。各命令境界を維持する経路か、周辺装置と割り込みの
観測タイミングを厳密に保存するスケジューラが必要。

他EG、MIDI/GS、ボイス管理、起動・パネル等も残っており、完全置換は未達。
検証はv1.21専用。ホスト内負荷、Windows/Linux、全音色は今回未検証。
