# 通常経路のカットオフ計算置換 — 2026-09-08

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

## 実装

controller置換を `d9299f5` としてcommit/pushした後の追加。
`00:473c..47fa` のカットオフ補間、天井制限、差分、変化率符号化を
`mcu_native::TryAdvanceCutoff` に置換した。各分岐の最後のRTSはH8に残す。
音源のフィルタ係数そのものやPCM演算精度を変更したのではない。

既存のv1.21 ROMハッシュゲートと割り込みマスクを使用。
control <= 0x7fff、天井添字 <= 127、selector <= 8、通常SRAM/ページを
満たさない入力は元のH8へ戻す。変化率の正規化ループは最大16回。
書き込み、レジスタ、SR、分岐ごとの命令数を保持し、周辺装置のクロックは
既存debtで1命令分ずつ処理する。音声スレッドに確保・ロック・I/Oは追加しない。

置換先が増えたため、毎命令の呼び出し判定をif列からPCのswitchに整理。
従来309bフックの機種条件は変更していない。
この判定変更も以下の性能値に含む。カットオフ計算だけの改善率ではない。

## 検証

- 2,599ケースで全汎用レジスタ、SR、SRAM、復帰位置、命令数が実ROMのH8と一致。
  補間の有無、最小添字、上下限、前回値と同値/±1、上昇/下降、selector 0〜8、
  乱数入力を含む。不適格入力12種類で状態を変更せずfallbackすることも確認。
- 通常起動→24音→CC1/7/16/17・channel/poly pressure→Note Offで
  347,676ステレオフレームがビット一致。
- カットオフ4,083呼び出し、331,423命令を置換。
- 既存TVA 4,390ケース、controller 1,024ケースとその通常再生経路も通過。
- Mac Release Shared Code（arm64/x86_64）ビルド成功。
  Logic内、Windows/Linux、全音色/GSの網羅確認は今回行っていない。

## 性能

[controller置換時](NATIVE_CONTROLLERS_2026-09-08.md)と同じ製品adapterハーネス。
macOS arm64 Release、48kHz/128 samples、program48、24音保持。
起動を除く120音声秒の計測スレッドCPU時間。H8-PC集計なし。
前後の順序を入れ替えて計測した。

| 順序 | controller置換まで / 今回追加後 | CPU秒 |
|---|---|---:|
| 1 | 追加前 | 7.263178 |
| 2 | 追加後 | 6.830355 |
| 3 | 追加後 | 6.840341 |
| 4 | 追加前 | 7.250779 |

平均7.256979 → 6.835348 CPU秒、**今回さらに5.81%削減**。
CPU/音声時間比は約6.047% → 5.696%。
全実行でpeak=0.642068、RMS=0.121042、underrun/MIDI dropなし。
カットオフのみを追加しif列のまま測った版では約1%減だったため、
置換先の判定コストも無視できない。ただし命令配列・最適化配置も変わるので、
差全体を分岐回数のみの効果と断定しない。

60秒アイドルの単発値は1.478930 → 1.465955 CPU秒。差が小さいため
アイドル改善を確定値として扱わない。Logic CPUメーターの値ではなく、
これまでの別時点の改善率を単純加算しない。

## 再実行

ROM指定は [TVAのconfigure手順](NATIVE_TVA_2026-09-08.md#再実行)と共通。

```sh
cmake --build /tmp/sc55-firmware-oracle-build --target sc55-firmware-oracle -j 4
ctest --test-dir /tmp/sc55-firmware-oracle-build -R '^native-tva$' -V
```

この既存テスト名でTVA/controller/cutoffと通常再生の差分検証を実行する。
