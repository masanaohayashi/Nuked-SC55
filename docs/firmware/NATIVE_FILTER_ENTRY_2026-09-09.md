# フィルター入口の単命令置換

TryStepFilterEntryでSC-55 v1.21の3e30..3e5b、14命令を追加。
ボイスのページ/パッチ参照を読み、モード>=2では履歴をクリアして4435へ渡す。
当初の3e3bのパッチ参照はEP=0のSRAMに限定（下記追加で拡張）。
制御レジスタEP変更によるex_ignoreも再現する。

線形逆アセンブルは3e2fのffから誤った命令境界を採る。
実際の入口は3e30。また3e42は5バイトの即値MOV.Bで、次命令は3e47。
H8デコーダーとの比較でこれらを確認した。

- 14×384＝5,376境界でPC/SR/全レジスタ/EP/ex_ignore/SRAMが一致。
- native-tvaの379,676ステレオフレームがビット一致。
- Mac Release Shared Codeビルド成功（署名なし）。

単命令の割り込み境界を維持し、確保・ロック・UI呼び出しを追加していない。
CPU高速化量とLogicでの動作は未測定。

## 通常経路の追加

3e5e..3e95の20命令を追加し、合計34命令。
モード値の倍化/フラグ設定、パッチ値保存、c8fcテーブル参照、
DP=3でのdcd2テーブルと間接参照、DP=0への復帰を実装。
EPで参照するパッチの読み込みはページ0のROM/SRAMとページ1〜4のROMに対応。
I/Oを含むページ0のe000以降、その他のページは既存H8へ戻す。

- 全34命令×384＝13,056境界でPC/SR/全レジスタ/DP/EP/ex_ignore/SRAM一致。
- EP=0〜4を試験。DP=3の命令は該当ページでH8と比較。
- 379,676ステレオフレームがビット一致、H8 fallbackは2,860,967→2,860,442。
- Mac Release Shared Codeビルド成功（署名なし）。

命令数の削減はCPU改善量を意味しない。

## 係数補正の追加

3e98..3ed3の25命令を追加し、合計59命令。
パッチbyte41と64の差、R2と4000の差から絶対値と符号を求め、
74d2テーブルの係数で乗算する。積の上位wordの下位byteと
下位wordの上位byteをMOV.B/SWAPで取り出し、必要な経路でNEGしてvoice[84]へ保存。
命令途中のフラグ、R2/R3および割り込み境界も維持する。
テーブル参照のネイティブ条件は偶数インデックス0..128。他はH8に戻す。

- 全59命令×384＝22,656境界でPC/SR/全レジスタ/DP/EP/ex_ignore/SRAM一致。
- 379,676ステレオフレームがビット一致。
- 同じ再生のH8 fallbackは2,860,442→2,860,067。
- Mac Release Shared Codeビルド成功（署名なし）。

CPU改善量は未測定。

## コントローラー補正の追加

3ed6..3f02の18命令を追加し、合計77命令。
127からc95c[R1]をbyte減算し、パッチbyte61の64からの偏差を用いて
74fcテーブル係数を選ぶ。MULXU.Wの下位wordを32767から引き、
経路に応じてNEGし、voice[-46]へ保存する。byte演算時のレジスタ上位byteも保持。
このテーブル参照も偶数インデックス0..128を対象とする。

- 全77命令×384＝29,568境界でPC/SR/全レジスタ/DP/EP/ex_ignore/SRAM一致。
- 379,676ステレオフレームがビット一致。
- 同じ再生のH8 fallbackは2,860,067→2,859,767。
- Mac Release Shared Codeビルド成功（署名なし）。

CPU改善量は未測定。3f05以降は
[深度の係数設定](NATIVE_FILTER_DEPTH_2026-09-09.md)で置換を継続。
