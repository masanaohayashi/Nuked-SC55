# 更新対象ボイスの走査

`TryStepVoiceScan`で5b0b..5b70の36命令を単命令C++化。
R1=23から逆順に676aのポインター表でvoiceを取得し、状態wordが18未満かつ
voice[-26]が0のボイスを選ぶ。cac4/cadcの関連ボイス番号に応じて5b73または
5bb4へ進む。走査後の別ループは各voice[-26]をクリアして5942へ戻る。
voice[-26]は318cからの出力処理でffに設定される走査マークと対応する。

この走査は割り込み可能なのでまとめて終状態を公開しない。
5b0bのEP設定にもex_ignore=1が必要であることを差分テストで確認し反映した。
SCBのデクリメントとffff判定はSRを変更しない。

既存ASMの5b19付近も境界が崩れている。
実デコーダーで検証した境界は5b19（wordと符号拡張即値18の比較、4byte）、
5b1d（BCC、2byte）、5b1f（voice[-26]のTST.B、3byte）。

条件はv1.21、CP/DP=0、traceなし。テーブルは偶数index0..46、
voiceを使う命令は正規24voice、cac4/cadcアクセスはR1<24に限定する。
条件外は状態を変更せずH8へ戻る。新しい確保・ロック・スレッド移動はない。

## 検証

- 36命令×384ケース＝13,824境界でPC/SR/全レジスタ/EP/ex_ignore/SRAMが一致。
- Release oracle: 379,676ステレオフレームがビット一致。
- H8 fallback: 3,383,922→3,274,788（109,134命令減少）。
- Mac Release Shared Codeビルド成功（署名なし）。

CPU改善量は未測定。5b73以降の関連ボイス更新経路は未置換。
周辺更新回数は変えていないため、命令数削減をCPU改善率として扱わない。

## 続き: 単独・関連ボイスのサービス接続

5b73..5c1dの54命令を追加し、走査ヘルパーは合計90命令。
cb48は走査index、cb4a/cb4cは処理対象voiceの保存場所として使われる。
単独経路は5c20→3985→3188→5855を呼び、関連ボイス経路はさらに
5ff5/3d44への呼び出しと、2個のvoiceの出力処理を行う。
呼び出し先の意味の完全な解析ではなく、引数保存・復元と制御フローの置換である。

ANDC/ORCのex_ignore、4個ずつのNOP、BSRの戻りアドレス保存を保持。
呼び出しを跨いだバッチ化や周辺更新の間引きは行わない。
BSRは偶数SRAMスタックかつTP=0に限定し、ガード外はH8へ戻す。
voice[-2]書き込みは正規voiceに限定する。

- 90命令×384ケース＝34,560命令境界でH8と一致。
  PC/SR/全レジスタ/EP/ex_ignore/SRAM（戻りアドレス含む）を比較。
- Release oracle: 379,676ステレオフレームがビット一致。
- H8 fallback: 3,274,788→3,186,852（87,936命令減少）。
- Mac Release Shared Codeビルド成功（署名なし）。

CPU改善量は未測定。呼び出し先にはまだH8が残る。
