# フィルターのLFO呼び出し接続部

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

`TryStepFilterConnections`で46c3..46daの6つの引数ロードと2つのBSR、
4448/47ee/47f4/47fa/4856のRTSを1命令ずつC++実行する。
2組のLFOはvoice[-120,+140,-96]と[-86,+148,-62]をR2/R3/R6へ読み込む。
BSRは戻りPCを既存スタックヘルパーで保存し、47fbへ分岐する。
RTSも既存スタックヘルパーを使う。

v1.21、CP/DP=0、traceなし、正規voiceを要求。
EPや割り込みマスク7は要求しない。各命令の状態を公開し、debtを追加せず
12cycleごとの割り込み境界を維持する。音声スレッド以外へ移動しない。
確保・ロック・UI呼び出しを追加しない。

## 検証

- 13命令×384ケースでPC/SR/レジスタ/SRAMがH8と一致。
  mask0..7、SR下位16通り、EP=1、正規voice24個を含む。
- Release oracleで379,676ステレオフレームがビット一致。
- H8 fallback: 3,644,347→3,587,004（57,343命令減少）。
- Mac Release Shared Codeを署名なしでビルド成功。

CPU時間・Logic内負荷は未測定。命令数削減をCPU改善率とはしない。
初期値/保持分岐などフィルター処理には未置換箇所が残る。
