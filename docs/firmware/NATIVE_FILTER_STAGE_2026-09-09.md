# フィルターEGの段階遷移

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

`TryDispatchFilterStage`で4443から段階ごとの処理入口までをC++化。
voice+101の無効化、位相+10の完了判定、6ac8の次段階、7896の初期化、
78aeの実行先テーブルを保持する。4469/4471/4479ではレート75..77と
目標88/90/92を選び、旧目標86を始点84へコピーする。
終了段階は4553、無効化時は4448のRTS手前へ戻す。

v1.21、CP/DP/EP=0、mask7、traceなし、正規voiceを要求する。
不正な段階値は変更前にH8へ戻す。SR、汎用レジスタ、命令数/debtを維持。
処理は既存audio経路内で、確保・ロック・I/O・UI呼び出しは追加しない。

## 検証

- 24,576ケース（12段階、位相4種類、無効化4種類、乱数128回）で
  H8とPC/SR/レジスタ/SRAM/命令数が一致。
- Release oracle native-tvaで379,676ステレオフレームがビット一致。
- 同一再生条件のH8 fallbackは4,238,291→4,195,814（42,477命令減）。
- Mac Release Shared Codeを署名なしでビルド成功。生成プロジェクト変更なし。

命令数削減はCPU時間削減率ではない。今回はCPU時間とLogic内負荷は未測定。
duration算出・位相更新・出力など、フィルターEG内部にはH8処理が残る。
