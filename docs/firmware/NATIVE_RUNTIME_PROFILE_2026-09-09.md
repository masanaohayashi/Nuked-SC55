# C++置換後の実行時間サンプル

Release計測器の24音(program48)、48kHz/128samples実行中を
macOS `sample`で5秒、1ms間隔で採取した。起動後のBEGINを確認してから
PID57982に接続。サンプル中の時間計測結果は比較用には使わない。

主スレッド3559サンプルのうち、top-of-stack（自身の処理）は次の通り。

|関数|サンプル|全体比|
|---|---:|---:|
|MCU_Step|986|27.7%|
|PCMSim_RenderFrame|523|14.7%|
|PCM_Update|497|14.0%|
|TIMER_Clock|349|9.8%|
|TIMER_ClockTmr|52|1.5%|
|MCU_Operand_General|252|7.1%|

MCU_StepのMCU_ReadInstruction呼び出し箇所（1182行）の枝は
子関数込み656サンプル（18.4%）。これは上表のデコーダー等を含むので加算しない。
MCU_Step自身には振り分けだけでなく、割り込み確認、native_debt消化、
cycles更新、UART/ADC確認なども含む。インライン化と最適化で行帰属が
曖昧な215サンプルもあり、27.7%を全て振り分けコストとは解釈できない。

## 次の実装判断

PCM単独が支配するという仮説は支持されない。未置換H8実行はなお有意で、
置換対象として残る。一方、単命令をC++へ移してもMCU_Stepの周辺更新と
タイマーは残るので、命令数減少ほど全体CPU時間が減らない構造がある。
ディスパッチコストが相殺しているかはこのサンプルだけでは未確定。

次は未置換の高頻度ループ（5bxx等）の意味を解析し、同時に
割り込み/周辺回路の観測境界を壊さずにまとめられる単位を検討する。
タイマーやPCM呼び出しを根拠なく間引く修正は行わない。
H8置換完了の目標は維持する。PCM最適化だけをもって代替完了とはしない。
