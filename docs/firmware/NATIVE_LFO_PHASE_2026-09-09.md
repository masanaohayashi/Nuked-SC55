# LFOディレイ・立ち上がりの単命令経路

`TryStepLfoPhase`で3b26..3b71の27命令を追加。
既存TryAdvanceLfoバッチが使えない場合に各命令をC++で実行する。
R1で指定する変調ブロックの+24のディレイ、+26の立ち上がり進行値を、
+16/+18の速度とac5aの経過量の積で進める。
32bit積と16bit進行値の加算で上位wordへcarryを渡し、ffffで飽和する。
ディレイ未完了は3bbc、立ち上がり完了は3baaへ進む。

ADDXの累積Z、TSTのcarryクリア、MOVのcarry保持を再現。
v1.21、CP/DP=0、traceなし、偶数SRAMブロックを要求する。
入口のR1設定2命令はブロック作成前なのでブロック範囲条件を適用しない。
割り込みmaskやEPに依存せず、debtを追加しない。
新しい確保・ロック・スレッド移動・周辺更新の間引きはない。

## 検証

- 27命令×384ケース＝10,368境界でPC/SR/全レジスタ/SRAMがH8と一致。
- Release oracle: 379,676ステレオフレームがビット一致。
- H8 fallback: 2,912,164→2,911,214（950命令減少）。
- Mac Release Shared Codeビルド成功（署名なし）。

この再生では大部分が既存バッチを使うため追加の命令削減は小さい。
CPU改善量は未測定。3b74以降の単命令経路は未置換。

## 続き: 立ち上がり係数の適用

3b74..3bb9の30命令を追加し、合計57命令になった。
ブロック+0/+2/+4の変調量について、負なら絶対値化してR5の係数を
掛け、積の上位wordを必要に応じて符号反転し、+6/+8/+10へ保存する。
立ち上がり完了経路は元の3値をそのままコピーする。
NEG/MULそれぞれのSR、中間のR2/R3、読み書き順序を維持する。

- 57命令×384ケース＝21,888境界でPC/SR/全レジスタ/SRAMがH8と一致。
- Release oracle: 379,676ステレオフレームがビット一致。
- H8 fallback: 2,911,214→2,910,914（300命令減少）。
- Mac Release Shared Codeビルド成功（署名なし）。

CPU改善量は未測定。3bbc以降の周波数・波形更新の単命令経路は未置換。

## 続き: 周波数補正と波形選択

3bbc..3becの19命令を追加、合計76命令。
ブロック+12のrateから7012のword表を引き、+14の補正を加える。
補正が負の経路で結果が28f6を超えれば0、正の経路なら28f6へ制限する。
ac5aの経過量を掛け、ブロック+20をindexとして74c4のジャンプ表を引く。
JMPはPCだけをR2へ変更し、SRを維持する。
テーブル条件はrate indexが偶数0..510、波形indexが偶数0..10。
範囲外の入力はH8へ戻す。

- 76命令×384ケース＝29,184境界でPC/SR/全レジスタ/SRAMがH8と一致。
- Release oracle: 379,676ステレオフレームがビット一致。
- H8 fallback: 2,910,914→2,910,264（650命令減少）。
- Mac Release Shared Codeビルド成功（署名なし）。

CPU改善量は未測定。各波形の更新本体（3bee以降）の単命令経路は未置換。
