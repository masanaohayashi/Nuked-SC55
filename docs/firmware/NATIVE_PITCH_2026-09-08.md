# 通常経路のピッチ変調・PCMレート変換 — 2026-09-08

[解析索引へ](../../FIRMWARE_RESEARCH_INDEX.md)

## 実装範囲

- `TryModulatePitch`: 5368..53e4。符号付き2深度の合成・6000飽和、
  波形の符号、16bit wrap、丸め付き積、24bit pitchへの加減と下限処理。
  2系統のLFOから通常再生中に呼ばれる。RTSとstackはH8側に残す。
- `TryConvertPitch`: 51e7..527c。基準音程と12000を引いた24bit差分から、
  除算、ROMテーブル、オクターブシフトでPCMレートを生成する。
  端数・負の差分・上限飽和を再現し、C8B0のレート値を更新する。
  後段の補正キャッシュ527c..5367は引き続きH8。

いずれもv1.21のROMハッシュ、有効ページ、interrupt mask、trace禁止、
正規24 voiceアドレスでガード。参照はROM/SRAMのみ。
全汎用レジスタ/SR/メモリ/命令数を再現する。
極端な低音程で長くなる元のシフトループはC++のシフトで計算するが、
元の命令数はdebtに保持し、周辺装置のクロックは飛ばさない。
JUCEの音声処理スレッドは変更せず、確保・ロック・UI呼び出しを追加しない。

## 対象選択

既存の24音＋controller変更計測では0x5300ページはH8命令数の3.24%、
0x5100ページは2.90%。CPU時間の割合ではない。
より命令数の多いROM2 44400..445ffは主にパネル表示のレベル集計だったため、
発音に直接関係する解析済みのピッチ計算を今回優先した。
