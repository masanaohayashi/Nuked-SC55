## 実際のfallbackを数える

oracleのmcu.cppだけに`SC55_ORACLE_H8_PROFILE`を定義し、MCU_ReadInstructionを
実行する直前でカウント。debt消化やC++単命令実行をH8として数えない。
製品ビルドには計測呼び出しを含めない。
`SC55_TVA_PROFILE=1 ctest --test-dir /tmp/sc55-firmware-oracle-build -R '^native-tva$' -V`
で従来H8側の分布とnative側の残存命令数を表示する。

起動後60Mcycles以降の24音・controller・portamento・Note Offシナリオ:

- H8 fallback: 5,143,894命令。
- CP0:4f51..53e4のピッチ領域: **0命令**。
- 379,676ステレオフレームが従来H8とビット一致。

この0は本シナリオの監査結果であり、起動全体・全音色・異常状態・他ROMの証明ではない。

| 残存256byte領域 | 命令数 | 残存全体の比率 |
|---|---:|---:|
| 003600 | 367,099 | 7.14% |
| 000300 | 346,765 | 6.74% |
| 044500 | 341,286 | 6.63% |
| 044400 | 340,279 | 6.62% |
| 000400 | 319,019 | 6.20% |
| 007f00 | 273,011 | 5.31% |
| 003500 | 234,596 | 4.56% |

命令数はCPU時間そのものではない。次は3500/3600の音量EG補間・出力更新を優先する。

## 性能と判定負荷の修正

macOS arm64 Releaseの製品adapter、48kHz/128samples、program48、24音保持120音声秒。
起動・ウォームアップは除外、測定中はビルドを並走しない。
比較元は`/tmp/sc55-perf-uYIHTJ/sc55-perf-before-unmasked`:
前回のマスク区間音程補正・段階ステップ追加時点のReleaseバイナリ。

単命令経路追加直後の前/後/後/前CPU秒:
4.155809 / 4.362361 / 4.392673 / 4.169219。
平均4.162514→4.377517秒、約5.17%増。

default dispatchにCP/ピッチ領域外の早期終了を追加し、非ピッチ命令が多数の
ピッチ範囲判定を通る負荷を削減。修正後/前/前/修正後CPU秒:
4.149592 / 4.145069 / 4.137920 / 4.167438。
平均4.141495→4.158515秒、約0.41%増。増加は大部分解消したが改善とは言えない。
全回peak=0.642068/RMS=0.121042、underrun/drop=0。
